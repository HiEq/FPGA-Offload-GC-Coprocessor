# 设计报告骨架（对应指南 3.3.5.3）

> 用法：按节填写，每节只写“可核查的事实 + 依据”。数字必须带命令、种子、位流哈希与日期。
> 失效条件：若作品不含 PL 逻辑（纯 HLS / 纯软件），第 3、4 节的划分内容需改写。

## 1. 选题背景与创新点
- 要解决的实际问题、现有做法的瓶颈（给出数据或引用）
- 前人工作与差异（表格：方案 / 做法 / 局限 / 本项目差异）
- 创新点 3–4 条，每条对应后文的一节证据

## 2. 设计原理与功能框图
- 框图（软/硬边界清晰，标注时钟域与接口）
- 数据流：谁产生、谁消费、缓冲在哪里
- 关键算法与状态机（列出状态与转移条件）

## 3. 软硬件划分依据与接口设计
- 划分依据：访存模式、并行度、延迟敏感度（用测量或估算支撑）
- 接口：寄存器映射表（地址/位域/读写/复位值）、数据面位宽与突发
- 一致性/同步：谁负责 cache 维护，屏障点在哪里

## 4. 优化过程（优化前后对比表）
| 版本 | 改动 | 关键指标 | 资源 | 时序 |
|---|---|---|---|---|
| v1 | 基线 | | | |
| v2 | … | | | |

- 每一步说明“为什么这么改”和“预期改善多少”，再给实测值

## 5. 大模型协作记录
- 提示词（原文）、模型回答要点、人工修正
- 自我纠错轨迹：哪一步判断错了，怎么发现的
- 智能体工作流（如有）：角色、输入输出、失败重试条件

## 6. 技能包的提炼过程
- 从哪些失败/观察中总结（对应 skill/ 的条目编号）
- 如何验证有效（在哪个项目、什么条件下复现）
- 边界：什么情况下不适用

## 7. 复现说明
- 环境（工具版本、OS、依赖）
- 命令序列（从零到出结果）
- 预期输出（关键行）与常见偏差
