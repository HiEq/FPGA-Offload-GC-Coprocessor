# RTL、构建与上板调试踩坑清单

本清单只收录会改变结论的故障：RTL 竞争、报告读错、构建产物不一致、板上部署错配。
每条给出判别信号、根因与处理；终端相关只保留会直接影响脚本执行的两条。

## 1. 位流重新综合后 md5 变化

- **判别**：同一套 RTL、同一版本 Vivado，两次综合的 `.bit` md5 不同。
- **根因**：布局布线不可比特复现。
- **处理**：以功能与时序为验收依据；发布资产记录 md5，重建的位流不替换已发布哈希，
  文档只引用发布值。

## 2. Vivado 批处理路径含空格报 `Could not open 'C'`

- **判别**：日志里路径被截断成单个盘符。
- **根因**：Tcl 拼路径未加引号，空格把路径截断。
- **处理**：路径统一加引号或花括号，或改用无空格的目录联接。

## 3. 资源与时序取自错误的报告或错误的行

- **判别**：同一工程两次统计的 LUT 不同（如 27,192 与 26,826）；或 WNS 在 placed 与
  routed 之间变号。
- **根因**：utilization 报告里 `Slice LUTs` 与 `CLB LUTs` 是两类统计；placed 报告早于
  布线，时序尚未收敛。
- **处理**：资源取 `*_utilization_placed.rpt` 的 `Slice LUTs` / `Slice Registers`；
  时序取 `*_timing_summary_routed.rpt` 的 WNS/WHS；只在同一次构建内比较。

## 4. 单拍 AXI 读的几何写死在 RTL 里

- **判别**：板上读回数据错位或总线报错，功能仿真用行为模型时却正常。
- **根因**：`ARSIZE=3`、`ARLEN=0`、`ARBURST=INCR` 是常量，地址按 8 字节对齐；行为模型
  不检查这些字段。
- **处理**：接入协议检查器，覆盖 `ARSIZE`/`ARLEN`/`ARBURST`、地址对齐、`ARVALID` 稳定性；
  负控把 `ARSIZE` 改错后检查器必须 FAIL。

## 5. `run_start` / `abort` 与在途读同拍

- **判别**：换图后的第一拍读到上一轮的残留数据；或换图后引擎挂住。
- **根因**：指针重装与 FIFO 弹出同拍；`RREADY` 未与 `run_start`/`abort` 门控；AR 已发
  未回时 flush 提前结束。
- **处理**：三处一起改：同拍不弹、`RREADY` 与丢弃分支门控、flush 退出条件加 `!ARVALID`；
  用三个定向 testbench 守护。

## 6. 命令 FIFO 同拍入队 / 出队

- **判别**：换图后下一轮发出上一轮的 AR 地址。
- **根因**：脉冲周期 `c*w` 越过重装的 `c*r`，或出队与入队同拍推进。
- **处理**：入队与出队都加 `!run_start && !abort`；testbench 断言脉冲后 `c0r == c0w`。

## 7. 队列满时静默丢对象

- **判别**：大图 `marked` 比 oracle 少，`STATUS` 却全为 0。
- **根因**：入队失败没有粘滞位，软件无法区分“图就这么大”和“对象被丢弃”。
- **处理**：`err_ovf` 粘滞并映射到 `STATUS[0]`；仿真用 `force q_full` 覆盖该分支，
  正常负载到不了满。

## 8. 位图探针写入后立刻读

- **判别**：读到上一个对象的位；或探针地址写不进去。
- **根因**：`BM_ADDR` 写入到 `BM_DATA` 有效之间有 2 拍延迟，期间改地址会让数据对不上。
- **处理**：写地址后固定等待 2 拍再读，读前不回写；地址写后回读校验，失败返回
  `0xFFFFFFFF`，调用方按“未知”处理并退回全量标记。

## 9. 12 位 ID 与 4096 边界

- **判别**：对象数为 4096 时最后一个对象永不被标记；或 31/32/33 附近位图错位。
- **根因**：ID 截断、位图字边界、`<` 与 `<=` 混用。
- **处理**：边界矩阵覆盖 0/1/2/max-1/max，另跑 4095/4096 与位图 31/32/33。

## 10. 上电停在 U-Boot 的 `Zynq>` 提示符

- **判别**：串口停在 `Zynq>`，后续命令被当成 U-Boot 命令执行。
- **根因**：`boot.scr` 只覆盖一种启动分支，或标记文件被删；启动窗口内收到任何字节都会
  中止 autoboot。
- **处理**：`boot.scr` 加默认分支；探活只读，看到 `login:` 或 `root@` 再写。

## 11. 内核 panic：`VFS: Unable to mount root fs`

- **判别**：`root=` 解析失败，分区列表只有 ram 设备。
- **根因**：DTB 未启用 SD 控制器，或 `root=` 写法与内核不匹配。
- **处理**：用镜像自带 DTB；`root=/dev/mmcblk0pN` 与 `rootwait` 成对使用。

## 12. 内核模块与镜像不配对

- **判别**：`insmod` 报 `version magic ... should be ...`。
- **根因**：模块与 `image.ub` 不是同一次 PetaLinux 构建。
- **处理**：用同一次构建的 SDK 重编模块；发布 zip 里模块与镜像成对放入，并核对 vermagic。

## 13. 改了串口波特率，登录仍是 115200

- **判别**：U-Boot 已是 921600，内核启动后 getty 又回到 115200。
- **根因**：`SERIAL_..._BAUDRATE` 只喂 U-Boot 与设备树，不改 sysvinit-inittab 里的
  `start_getty`。
- **处理**：在 rootfs postprocess 里重写 `start_getty` 的波特率；启动后用 `stty` 核对。

## 14. 卡上只推了一个测试脚本

- **判别**：`ModuleNotFoundError`；或同一测试在两处副本表现不同。
- **根因**：卡上 `tests/` 是整套副本，脚本之间有 import；改名后旧文件仍留在卡上。
- **处理**：用 `push_tests.ps1` 整套推送，推完做 md5 校验，删除旧名副本。

## 15. 串口脚本无响应

- **判别**：推送脚本报 `shell did not answer 'stty -echo'`，手工回车却有提示符。
- **根因**：脚本默认波特率与控制台不一致（115200 与 921600）。
- **处理**：默认值统一为 921600；终端侧关闭状态栏重绘，避免提示符匹配失败。

## 16. `git push` 被重置但 API 正常

- **判别**：`Connection was reset` 或 TLS 超时，同一台机器的 `gh api` 可用。
- **根因**：到 `github.com:443` 的链路被中间设备重置。
- **处理**：用 API 建 blob/tree/commit/ref；推送后执行 `git fetch` 与
  `git reset --keep origin/<branch>` 对齐本地，避免出现假的 ahead/behind。

## 失效条件

- 第 4–9 条针对本项目这种单拍、单时钟域、12 位 ID 的 AXI HP 读引擎；换成突发读或
  HLS 接口后需要重写对应的检查方法。
- 第 12–14 条依赖 PetaLinux + sysvinit + FAT32 数据分区；用 PYNQ 镜像或 ext4 根文件
  系统时只保留“模块与镜像成对”这一条。
