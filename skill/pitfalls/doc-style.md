# 技术文档写法约束与常见退回项

本文件把评审中反复要求修改的项固化为规则。新增或改写文档时逐条对照；每条都给出
“错误写法 → 正确写法”，便于自查。

## 1. 使用书面语，不使用口语

- 错误：`看串口日志` / `跑一次测试` / `搞不定` / `坑`
- 正确：`查看串口日志` / `执行一次测试` / `无法完成` / `缺陷`
- 判定：把动词换成“查看、执行、配置、校验、生成”，把评价词换成事实描述。

## 2. 一句只表达一个意思

- 错误：`对象体留在 DDR，引用关系抽成 side table；PL 做标记，PS 负责回收。`
- 正确：`对象体驻留 DDR，引用关系整理为连续的 side table。标记与空闲扫描由 PL 完成，分配与回收策略由 PS 软件负责。`
- 判定：出现“；”再接“——”、或一句话里超过两个主语时，拆句。

## 3. 正文不使用引用块（灰色方框）

- 错误：整段说明前面加 `> `。
- 正确：改为普通段落；仅在需要与正文区分的警示性内容时保留，且一篇不超过一处。

## 4. 删除冗余重复

- 同一事实只写一次；后文引用前文时写“见 §X”，不要复述。
- 表格已给出的数字，正文不再逐个重复，只写结论与出处。

## 5. 数字必须可追溯

- 每个性能或资源数字都要能回答：哪条命令、哪个种子、哪个位流/镜像哈希、哪一天。
- 没有这四项时标注 `historical/unverified`，不要与当前数据混排。

## 6. 表格列名用名词，不用问句或口语

- 错误：`做什么` / `看什么` / `一句话`
- 正确：`功能` / `内容` / `用途` / `说明`

## 7. 术语统一

- 同一对象只用一个名字（例如“位流”不混用“比特流”；“镜像”不混用“image”）。
- 首次出现可写“中文（英文）”，之后只用中文。

## 8. 标题层级与顺序稳定

- 每节先给结论，再给依据；实验数据放在“验证结果”，限制放在“已知限制”。
- 不用“其它/杂项”收尾，把内容并入相应章节。

## 9. 命令与路径可复制

- 代码块内只放可直接执行的命令；占位符用 `<name>`，不用“某路径”。
- 文档中不出现本机绝对路径（`<drive>`、`<home>

## 10. 提交前自查清单

1. 全文搜索口语词：`跑`、`搞定`、`坑`、`其实`、`挺`、`一句话`。
2. 全文搜索 `^> `，确认引用块不超过一处。
3. 抽查任意三个数字，是否都能在 `tools/logs/` 找到出处。
4. 表格列名是否为名词。
5. 是否出现绝对路径。

## 失效条件

- 面向非技术读者的宣传材料（如海报）可放宽第 1、2 条，但数字仍须可追溯。
